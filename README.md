# E-commerce Order Management System: Business Analysis Case Study

A business analysis case study for a fictional D2C retailer, ShopKart, covering the full order lifecycle from checkout to refund. It is a portfolio project, not employment experience. Stakeholder interviews are simulated.

**Start with** [`15-final-summary/final-summary.md`](15-final-summary/final-summary.md) for the 5-minute version.

## Contents
| Folder | What's inside |
|---|---|
| `02-stakeholder-analysis` | Power/impact analysis and engagement strategy |
| `04-business-objectives` | SMART objectives O1 to O6 |
| `05-scope` | In scope, out of scope, deferred |
| `06-assumptions-constraints` | A1 to A6, K1 to K5 |
| `07-as-is-to-be-process` | As-Is and To-Be diagrams, narratives, pain points P1 to P13 |
| `08-requirements` | Business and functional requirements, NFRs, business rules, use cases, edge cases |
| `09-user-stories` | User stories with Given/When/Then criteria |
| `11-data-and-api-analysis` | Logical ERD, API inventory and specs, integration risks |
| `12-traceability-matrix` | Pain point to objective to requirement to test |
| `13-uat-scenarios` | Business acceptance scenarios |
| `14-risks-and-dependencies` | Project risk register and dependencies |
| `15-final-summary` | Findings, recommendations, limitations |

## Suggested reading order
Final summary → pain points → business requirements → use cases → traceability matrix → risks.

## How the IDs connect
P (pain point) → O (objective) → BR → FR → US / UC → UAT. Each document lists the IDs it derives from, so any item can be traced in either direction.

## Tools
Mermaid and draw.io (diagrams), Markdown and Excel (documents), Postman (API examples).
